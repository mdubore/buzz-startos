# Buzz 0.2.0-main.20260726.h.7.m.57.s.31.sha.dd.222.a.5:0

## Release Scope

This is the first StartOS package for the upstream Buzz development snapshot
at:

```text
dd222a509b156ba52ed3219e895d7bf1cf322c92
```

It packages the Buzz relay/backend plus PostgreSQL, Redis, MinIO, and the MinIO
client for the StartOS v0.4.0 release line. Distribution is **sideload only**;
this release is not published to a StartOS registry.

The release bundle uses separate native artifacts:

- `buzz_x86_64.s9pk`
- `buzz_aarch64.s9pk`

No universal archive is provided.

## Included StartOS Integration

- Critical first-run owner and immutable canonical-URL setup
- Private relay membership actions for `member` and `admin`
- Native multi-daemon startup, bucket initialization, database migration, S3
  conformance, and composite Buzz/MinIO health
- Stable install-only service secrets
- Logical PostgreSQL backup plus wrapper state, Redis AOF, and authoritative
  MinIO object storage
- Architecture-specific image pins and live tag-drift verification

## Backup Boundaries

Included:

- SDK-managed logical PostgreSQL dump
- `startos` wrapper state and stable secrets
- `redis` AOF continuity data
- `media` MinIO data, including authoritative media and durable Git objects

Excluded:

- raw `postgres` volume files
- disposable `git-cache`

Restore preserves the owner, canonical URL, relay identity, database and Redis
passwords, MinIO credentials, Git-hook HMAC secret, membership data, events,
media, and durable Git objects.

## Security And Compatibility Limits

- The source is an upstream `main` snapshot, not a stable Buzz release.
- The package runs the backend. The external desktop client supplies the full
  UI; upstream mobile clients are still under development.
- The canonical community URL is immutable. Losing that StartOS address blocks
  startup until the same address is restored.
- Tenant-bound APIs and WebSockets reject unknown hosts, although generic
  NIP-11 or static shell responses may occur before tenant binding.
- Media GET/HEAD is link-accessible through the relay. Media links are not
  automatically discoverable, but possession of a link is sufficient to read
  it.
- Normal clients authenticate with NIP-42 and NIP-98. No manual generic-token
  credential or StartOS token-management action is exposed.
- Invite redemption in the limited browser surface requires a NIP-07 signer.
- Hosted/background iOS push delivery is disabled; ordinary relay connectivity
  is unaffected.
- The upstream admin dashboard/API and full browser client are disabled.
- Start SDK 2.0.9 may include the PostgreSQL password in local restore error
  argv/log output if password restoration fails. Treat exported restore
  diagnostics as sensitive.

## Device Evidence Still Required

All items below remain unrun on **both x86_64 and aarch64**:

- sideload and clean installation;
- initial owner and canonical-URL setup;
- canonical HTTP route behavior;
- WebSocket upgrade, NIP-42 authentication, and event round trip;
- member/admin add, list, remove, and owner rejection;
- media upload and link-accessible retrieval;
- NIP-98 Git create, push, and clone;
- restart persistence;
- `git-cache` deletion and MinIO-backed hydration;
- backup and restore;
- wrong-`Host` rejection for tenant-bound traffic;
- composite health failure when MinIO is unavailable;
- startup and steady-state CPU, memory, disk, backup size, and timing
  measurements.

The final architecture archives and `SHA256SUMS` must also be rebuilt from the
release commit before distribution. See
